## 点一下更新，什么都不动

v1.29.0 发布了，落在 v1.28.0 之上。插件已经装着的，**Obsidian → Settings → Community plugins** 里有个 **Update** 按钮。点一下。

v1.28.0 加的能力，全部要先打开才会生效。唯一默认开启的改动——问题怎么对上页面——带了一条回退开关。所以除非你主动去找，你的 Wiki 不会有任何变化。

下面这些，是以前做不到、现在可以了的事。

## 它找到的，就是你想找的那一页

这一条改变了你用这个插件的方式。

以前你提问，插件拿你的词去比页面标题、别名和一句话摘要。比的不是页面。**正文**——通常是一页上最长的文本，也是答案真正待着的地方——从来没被看过。如果你的问题和标题恰好没用同一批词，检索就会掉进一条更慢、更贵的路：让模型去猜你想说什么。

现在整页参与打分，标题和正文一起。于是你顺口说出的那句话，能找到你半年前写的那一段，哪怕两边几乎没有共同的词。用中文问一篇英文写的页面，或者反过来——页面照样浮上来。

还有两件小事跟着一起来了。搜索之前，问题本身会被铺开一次——先补上你自己 Wiki 提供的相关词，再补上模型从第一轮结果里提的词——所以一个问题即使只是绕着说，也能走到该去的地方。而这些工作现在每会话只做一次，不再每个问题做一次；这就是为什么打开 vault 之后的第一个问题略慢一点，之后都不会。

**"怎么问都找得到"是真的承诺，而如果它在你的库里失灵了，有路可退。** Settings → Advanced → **Legacy query scorer** 把排序原样恢复到上一版。默认关闭，因为新版在这套东西被测量过的那些库上更好——但你的库不在其中，所以这个开关归你。

你现在也能看见发生了什么。答案上方那一行大概长这样：`🔍 12 pages · ⚡ BM25F+PPR · 📚 4 sources`——检索加载了几页、实际跑了哪几条通道、答案用了几处来源。以前它不看情况就写上模型的名字，明明没调过模型也写，于是图通道在干活的时候，它照样成了"发生了什么"的答案。把鼠标停上去看明细：扩展补了几个词、检索带了几轮对话。

## 模型爱思考，摄入也不会再挂

会推理的模型在动笔之前先花输出预算去想。插件以前声明一个固定上限，而一个想得够狠的模型可以在吐出第一个实体之前就把这份预算花光——然后交回一个空批次。更糟的是，你看到的报错是在怪你的文件：*这份源文件对模型的上下文窗口来说太大了*。你的文件没问题。预算错了。

抽取现在声明模型自己的输出上限，让它写完就停——没用掉的上限不花钱，给少了却要赔上整个回合。哪家服务商不接受这个上限，插件会在第一批里对折两次学会它，而不是让整轮失败。

修这个问题顺带给出三个控件，都在 **LLM Configuration** 下面：

- **Thinking level** —— Default / Low / Medium / High。Default 什么都不发，让服务商自己决定，一般这也是最对的。服务商各自把档位翻译成自己的说法，所以同一个档位在不同模型上意味着不同的量。
- **Model context window** —— 确定真实值而且不大的时候填上，声明出去的上限就永远不会超过窗口本身。一个 8K 窗口的本地模型不会收到 128K 的请求。
- **Max output tokens per call** —— 这个控件一直存在，但对多数服务商是藏起来的，偏偏包括最容易撞上这个问题的那些。现在它出现在每个服务商的 LLM Advanced Parameters 里，就挨着花掉它的那个档位。

而当一次运行真的把预算用完了，报错会说原因是推理，而不是指向一个根本不存在的设置项。

## 笔记里的图片也算证据

很多笔记真正的内放在一张截图里：别人贴过来的表格、下面那段正文正在讲的那张图、你在总结的那篇论文里的一张插图。这些图片以前对摄入是完全不可见的。

打开 Advanced 设置里的 **Analyze embedded images during Markdown ingestion**，每一个符合条件的本地内嵌图片——`![[…]]` 或 `![…](…)`——就会跟它最近的几段正文一起被读，于是图片落在指向它的那段文字同一页上。图片按包发送，所以一篇笔记不受图片张数限制；单张有上限，动图只发一帧静帧，远程 URL 永远不下载。如果你想回头看模型到底看到了什么，再打开 **Save embedded image visual evidence to source page**，它会在来源页上写一个可折叠小节。

默认关闭。[文档摄入指南](/zh/blog/posts/pdf-ingest-guide/)同时讲了这一条和另外五条入口，以及每条入口把你的文件送到哪里。

## 答案的引用像论文

引用会按首次出现的顺序编成 `[1]`、`[2]`、`[3]`，同一处再被引用时编号不变，页脚的参考文献可以点。追问的时候编号保持稳定，所以你可以直接说"第三处来源"，意思不会飘。

输入框会随内容长高，不再在固定的小框里滚动；**clear history** 现在真的会清掉记录。

## 需要自定义请求头的端点

有些服务商不给你加个头就不理你：路由头、租户 id、会话 key。现在 API Base URL 正下方有一个自由文本的 **Custom Headers** 字段——一行一个 `Name: value`，随每个请求一起发，空行和 `#` 注释会被忽略。它自带 OpenCode 的预设，另有一个给说 `/v1/responses` 而不是 `/v1/chat/completions` 的端点用的变体。

修这件事的时候，顺手还找到了另一件。有些环境会拒绝浏览器的跨域请求，以前这意味着每一段流式回答都悄悄退化成一次性吐出——你盯着转圈，然后整段一起出来。现在被拒的来源会被记住，流式会改走桌面端传输重试一次。重试也失败的话，这次失败会被记录下来，而不是被吞掉。

## 几个更小的改动

- **Obsidian 排除的文件，现在处处生效。** 你本来就能在 Obsidian 里排除笔记，手动挑文件时插件也一直尊重它。监视文件夹没有——你排除掉的那篇笔记，只要你一编辑它，照样会被摄入。现在不会了。
- **一份标签词表。** 提供给模型的标签、写盘时把关的标签、lint 检查的标签，现在是同一份列表——由你笔记里的嵌套标签、已有页面上的标签、以及 Settings 里的自定义列表共同构成。列表之外的值会被丢弃，永远不会写盘，所以模型被提供的东西，就是最终落到磁盘上的东西。
- **机器生成的文件名不再变成实体页。** 摄入一篇文件名本身就是一串 ID 的笔记——UUID、时间戳——以前有时会生成一个拿那串 ID 当名字的实体页，正文只是把这篇笔记重讲一遍。这类页面没有了。
- **一个枢纽页拉不动全场。** 相关页列表做了整形，一个到处被链接的页面不再把每一页都往自己那边拽；每一页都带的那些链接，权重也更低。

## 怎么拿到

- **已经装着？** **Obsidian → Settings → Community plugins → Update**。点一下。
- **新用户？** **Obsidian → Settings → Community plugins → Browse → 搜 "Karpathy LLM Wiki" → Enable**，或者用首页的 [Add to Obsidian](/) 按钮。

两个版本的发布说明分别在 [v1.29.0](https://github.com/green-dalii/obsidian-llm-wiki/releases/tag/1.29.0) 和 [v1.28.0](https://github.com/green-dalii/obsidian-llm-wiki/releases/tag/1.28.0) 页面。检索这次重写有单独的深入文章：[深入解析（7）：Query 流水线内部](/zh/blog/posts/query-engine-pipeline/)。
